# Gboard for macOS

[English](README.md) | [简体中文](README.zh-CN.md)

GboardIME 是一款 macOS 中文输入法。它通过自定义的 ARM64 ELF 加载器，在 macOS 上运行 Android 版 Gboard 所用的原生 HMM 拼音引擎。

> [!IMPORTANT]
> **本项目不包含任何 Google 二进制文件或数据。** 用户须自行提供通过合法途径获取的 Gboard APK。详情请参阅 [NOTICE](NOTICE)。

## 功能

### 引擎

- **原生拼音引擎**：在 Apple 芯片的 Mac 上直接运行 Gboard 原生 HMM 拼音引擎。
- **离线候选生成与排序**：候选生成和神经语言模型重排序都在本地完成。
- **上下文感知排序**：参考光标前已上屏的文字调整候选顺序。例如，单独输入 `bushu` 时首选通常是“部署”，而在“我对这里很”之后首选会变为“不熟”。

### 输入

- **分段选词**：选中候选时只消耗它对应的拼音，其余部分保留。例如，输入 `nihao` 后选择“你”，`hao` 会留下来继续选词。按退格可撤销这次选择。
- **拼音切分显示**：拼音栏按引擎的实际切分显示，例如 `fang'an`；手动输入撇号分隔时显示为 `xi'an`。
- **拼音纠错**：借助 Gboard 内置纠错处理字母颠倒、漏打和多打，并在拼音栏标出改动。例如，`nihoa` 得到“你好”，`zhonguo` 得到“中国”。
- **双拼按键纠错**：独立于拼音纠错，有单独的开关。双拼输入时纠正误按的同排相邻键和音节内颠倒的两键，例如小鹤 `uhjd` 仍得到“上海”。
- **模糊音**：可选开启 12 组易混读音。例如，开启 l/n 后输入 `hulan` 可得到“湖南”。
- **中英混输**：在拼音输入中直接给出英文单词。例如，`woyaogithub` 得到“我要GitHub”，`yongpythonxie` 得到“用Python写”。
- **双拼**：支持六种双拼方案，默认仍为全拼。例如，小鹤双拼输入 `nihc` 得到“你好”。
- **u 模式拆字**：全拼下以 `u` 开头，依次输入各部件的拼音来打不会读的字。例如，`uniuniuniu` 得到“犇”，`ushuiguyue` 得到“湖”。拆字候选排在前面，英文等原有候选仍在其后。
- **下一词预测**：上屏后由引擎预测接下来的中文词。例如，上屏“生日快”后会预测“乐”。
- **简繁切换**：将候选词和下一词预测实时转换为繁体中文。
- **`?123` 符号面板**：共 6 页的中文与全角符号面板。

### 个性化

- **自动学习**：自动记住用户选择的中文、中英混合词组和英文单词，保存在本地用户词典中。
- **删除与撤销学习词**：按 `Shift+退格` 删除学习来的候选；刚上屏学习词后按退格可撤销这次学习。
- **学习词管理**：浏览、搜索、编辑学习词，并支持导入和导出。
- **快捷短语**：把自定义缩写展开为短语。例如，`dz` → 北京市朝阳区建国路 88 号。

### 界面

- **原生 macOS 界面**：基于 InputMethodKit 和不抢占焦点的 `NSPanel`。macOS 26 及以上的候选窗口采用 Liquid Glass，更早的版本使用毛玻璃面板。

## 环境要求

- 搭载 Apple 芯片、运行 macOS 13.0 或更高版本的 Mac
- Xcode 或 Xcode Command Line Tools（没有 `xcodebuild` 时，`build.sh` 会改用 `swiftc` 构建）
- `jq`（`brew install jq`）

## 安装

```bash
# 1. 解包 APK 并下载词典数据
#    （也可传入 .apk 文件）
./setup.sh --xapk /path/to/com.google.android.inputmethod.latin.xapk

# 2. 构建并安装
./build.sh install
```

> [!IMPORTANT]
> 添加输入法之前，须先注销并重新登录。

然后添加输入法：

**系统设置 → 键盘 → 文字输入 → 编辑 → + → 简体中文 → GboardIME**

脚本的全部选项见[开发](#开发)。

## 使用

在菜单栏的输入法菜单中切换到 GboardIME，即可输入拼音。

### 按键说明

| 按键 | 操作 |
|------|------|
| `a-z` | 输入拼音字母 |
| `;` | 微软／紫光双拼输入过程中作为双拼按键，其余情况输出中文标点 |
| `1-9` | 选择当前页对应序号的候选词或下一词预测 |
| `-` | 显示上一页候选词或预测 |
| `=` | 显示下一页候选词或预测 |
| `空格` | 上屏当前选中的候选词或第一个预测 |
| `←` / `→` | 移动候选光标，可跨页 |
| `退格` | 删除最后一个拼音字母；若部分选词之后输入的字母已删完，则撤销该次选词；刚上屏学习词后按下（不带修饰键）时，同时撤销该次学习 |
| `Shift+退格` | 输入过程中，从用户词典删除当前选中的学习词候选 |
| `'` | 输入过程中插入拼音分隔符（如 `xi'an`），其余情况输出中文引号 |
| 其他标点 | 先上屏当前选中的候选，再输出对应的中文标点（如 `,` → `，`、`\` → `、`） |
| `Esc` | 取消当前输入或关闭下一词预测 |
| `回车` | 直接上屏未转换的拼音（连同已部分选定的文字） |
| `Shift` | 切换中英文模式（开启“单击 Shift 切换中英文”时）；若有未完成的拼音，先原样上屏 |
| `Cmd+Shift+F` | 切换简体／繁体中文（中文模式下） |
| `Ctrl+1` / `Option+?` | 打开或关闭 `?123` 标点与符号面板（中文模式下） |
| `Caps Lock` | 在 macOS“文字输入”设置中启用后，在 GboardIME 与 ABC 之间切换；若有未完成的拼音，先原样上屏。未用于切换时，开启 Caps Lock 后输入的字母作为大写英文直接上屏 |

补充说明：

- **下一词预测**：也可以点击预测上屏；上屏后会继续给出新的预测。预测只响应 `1-9`、`-`、`=`、`空格` 和 `Esc`，其他任意键会关闭预测，该按键照常处理。
- **符号面板**：也可以从输入法菜单的“标点与符号 (?123)”打开。按 `1-9` 或 `空格` 选择符号上屏，`←` / `→` 移动光标，`-` / `=` 翻页。`Esc`、`回车` 或 `退格` 关闭面板；其他任意键会关闭面板，该按键照常处理。
- **删除学习词**：`Shift+退格` 只删除完全来自用户词典的候选，相当于 Gboard 中长按候选词的“移除建议字词”。选中这类候选时，设置按钮左侧会显示“⇧⌫ 删除学习词”提示（仅当“拼音显示位置”设为“候选窗口”时）。
- **撤销学习**：上屏学习词后立即按退格，会撤销这一次学习，并照常删除文字。

### 设置

在输入法菜单中选择“设置…”，或点击候选窗口中的齿轮按钮，即可打开设置窗口。所有更改自动保存。

**输入**

- **拼音方案**：全拼（默认），或小鹤、自然码、微软、智能 ABC、紫光、拼音加加六种双拼。拼音栏显示方案的原始按键。修改在本次输入结束后生效，并保留分段选词和学习记录。微软和紫光方案在输入过程中支持 `;` 键。
- **单击 Shift 切换中英文**（默认开启）：单击 Shift 在中英文之间切换。英文模式是临时的，切换回本输入法或切换应用、输入框时恢复中文。关闭后恢复为中文，不影响系统的 Caps Lock 设置。
- **繁体中文**（默认关闭）：将候选词和下一词预测转换为繁体中文（也可按 `Cmd+Shift+F`，或在输入法菜单中选择“切换为繁体中文”／“切换为简体中文”）。

**模糊音**

- 12 组读音可分别开启：z/zh、c/ch、s/sh、an/ang、en/eng、in/ing、l/n、f/h、r/l、k/g、ian/iang、uan/uang。默认全部关闭。修改立即生效，无需重启，并保留正在输入的拼音、手动分隔和学习数据。

**纠错**

- **拼音纠错**（默认开启）：使用 Gboard 内置纠错处理拼写中的字母颠倒、漏打和多打，例如 `nihoa` → “你好”。Gboard 原版没有这个开关；关闭时从解码器配置中去掉加载 `PinyinCorrectionModel` 的 `CorrectorSetting`。
- **双拼按键纠错**（默认开启）：双拼输入达到 4 键时，同时把每个按键解码为同一排左右相邻的键，并把每个音节的两键按颠倒顺序解码。手动输入的 `'` 两侧的键不会被对调。拼音栏标出被纠正的按键。
- **纠错标记**：“删除线与插入高亮”（默认：多打的字母加删除线，补上的字母显示为橙色）、“仅颜色”或“隐藏标记”。只影响显示。
- **纠错对齐**：决定拼音栏中改动的对齐方式：
  - “增删标记”（默认）：基于 LCS。
  - “交换标记”：把相邻颠倒的两个字母按正确顺序一起标为橙色。例如，`nihoa` 显示为 `ni'hao`，其中 `ao` 为橙色。

  切换立即生效，可搭配全部三种标记样式；只影响显示，不改变原生候选生成。

**候选与预测**

- **下一词预测**（默认开启）。
- **上下文感知**（默认开启）：读取光标附近的文字以改善排序；关闭后只根据刚上屏的内容预测。
- **每页候选数**：5 到 9 个（默认 9 个）。

**外观**

- **候选窗口主题**：跟随系统（默认）、浅色或深色，适用于所有 macOS 版本。macOS 26 以前，浅色和深色主题使用 Gboard 官方 Google Blue 配色。
- **候选窗口不透明度**（仅 macOS 26 以前）：调节候选窗口不透明度（默认 70%），调低后透出更多毛玻璃效果。macOS 26 及以上使用 Liquid Glass，透明度跟随系统设置。
- **拼音显示位置**：候选窗口（默认）、输入框（原生，使用应用自带的 marked text）或隐藏。

**快捷短语**

- **启用快捷短语**（默认关闭）：输入完整缩写时，对应短语作为首选候选出现。在“管理快捷短语…”中可以添加、编辑、删除、搜索，并以 JSON Lines 文件导入和导出。缩写为 1–32 个字母；短语须为单行、不超过 1000 个字符，可以是中文、中英混合或纯 ASCII（如邮箱地址）。选择快捷短语不会记入学习词。

**个性化**

- **学习输入习惯**（默认开启）：关闭后停止学习新输入，已有学习数据保留。
- **用户词典自动保存间隔**：15 分钟、30 分钟、1 小时或 4 小时（默认）。退出输入法时也会保存。
- **学习词管理**（“管理学习词…”按钮）：列出已学习的中文和英文词及其读音、词频。支持搜索、排序、多选删除、修改词频，以及以 JSON Lines 文件导出和导入。导入只补充缺少的词，并提高较低的词频。
- **清除学习数据**（“清除学习数据…”按钮）：确认后清除中英文用户词典中的学习记录，不影响系统词典或设置。此操作无法撤销。

> [!NOTE]
> 系统词库中本来就有的词，删除学习记录后仍会出现在候选中。通过简拼（如 `cs`）学到的词不会列出，因为 Gboard 的导出接口不包含它们。

## 工作原理

项目由三层组成：

1. **ELF 加载器**：把 ARM64 版 `libintegrated_shared_object.so` 直接加载到 macOS 进程内存中，处理重定位、符号解析和 TPIDR（线程本地存储）修补。
2. **JNI 兼容层**：模拟一个最小的 Android JNI 环境，让原生引擎能够初始化、加载词典数据包并处理输入。
3. **macOS 输入法前端**：基于 Swift、SwiftUI 和 InputMethodKit，负责捕获按键、驱动引擎，并在 SwiftUI 面板中显示候选词。

实现细节：

- **上下文窗口**：沿用 Gboard 原生的 TARGET_TOKEN 上下文注入机制。中文保留最近 5 个 UTF-16 代码单元，英文保留最近 20 个；遇到标点、空白或语言边界时停止截取。
- **中英混输**：使用 Gboard 的英文 token 与系统词典。
- **双拼**：直接使用 Gboard 原生 token 词典。
- **u 模式拆字**：Gboard 没有部件数据。本项目自行编写了约 7400 字的拆分表 `chaizi_characters.tsv` 和部件读音表 `chaizi_components.tsv`，未取自任何第三方拆字数据。构建时由 `scripts/gen_chaizi_tables.py` 编译成静态查找数组，放进二进制的只读数据段，查询时直接读取，无需解析。
- **双拼按键纠错**：Gboard 内置纠错只针对全拼拼写，因此改用原生输入格：每个按键连同同排左右相邻键作为低分 `ScoredInput` 候选一起追加（与 Gboard 触屏空间模型相同），每个音节的两键再加一条颠倒顺序的输入边（与 Gboard 韩语解码器相同）。不足 4 键的输入保持原样，以保留单音节和简拼。
- **繁体中文**：用户词典学习和上下文排序始终使用简体原词。
- **用户词典**：中文和中英混合词组写入 `user_dict_3_3`，纯英文单词写入 `user_dict_3_3_english`，均位于 `~/Library/Application Support/GboardIME/`。两者默认每 4 小时保存一次（可在设置中调整），应用退出时也会保存。
- **纠错对齐**：“增删标记”使用 LCS，“交换标记”使用限制性 Damerau-Levenshtein 距离（DL/OSA）。
- **Liquid Glass**：macOS 26 及以上的候选窗口使用 `NSGlassEffectView`，遵循苹果设计规范：无着色的常规玻璃、系统文字颜色、强调色选中项。透明度跟随系统“外观”和“降低透明度”设置。

## 开发

### `setup.sh` 选项

```
--xapk PATH     Gboard XAPK 或 APK 文件路径（必需）
--dict PATH     使用本地词典 ZIP 文件，而不从网络下载
--locale CODE   词典语言/地区：zh_CN（默认）、zh_TW、zh_HK 或 ko
```

### `build.sh` 命令

```
build       构建应用（默认）
install     构建并签名，然后安装到 ~/Library/Input Methods
uninstall   从 ~/Library/Input Methods 中卸载
clean       清理构建产物
```

### 反编译（可选）

`./decompile.sh` 会把 Java 源码反编译到 `gboard_apk_source/jadx/`，供逆向分析使用。需要先 `brew install jadx`；构建时不需要这一步。默认读取 `xapk_unpacked/com.google.android.inputmethod.latin.apk`；该文件不存在时（例如 `setup.sh` 用的是普通 APK），请用 `./decompile.sh --apk /path/to/gboard.apk` 指定。

### 测试

```bash
./test.sh
```

依次运行 C 语言引擎测试和 Swift 输入法测试。
